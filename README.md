Ode: a short poem of praise

## The toy implementation, and how to check it yourself

`ode/` is an initial, toy-scale implementation of `SPEC.md`: an executable
specification, a compiler to a straight-line byte machine (ODE8), a
deterministic emitter, a small independent checker that proves the emitted
bytes compute the specification on *every* input (by exhaustion over the
whole domain), and an assurance map generated from the checker record.
Nothing is trusted between the specification and the checker.

Every definition, expression, program, certificate, and record is a
canonical s-expression (`ode/canon.py`): symbols and integers in nested
lists, one space between elements, no other whitespace, a definition's
name the BLAKE3 hash of that form. One syntax for everything, small
enough that its reader is a few dozen lines.

Verify the worked example end to end (Python 3, no dependencies):

```sh
pypy3 -m unittest discover -s tests     # 11 tests, incl. mutants the checker must reject
pypy3 -m ode build examples/mix.sexp examples/build
pypy3 -m ode check examples/build       # ACCEPT, 65536 cases
pypy3 -m ode run   examples/build 60 165   # 174
pypy3 -m ode assure examples/build      # writes and prints examples/build/assurance.md
```

## The BLAKE3 slice: G and one compression, proved for all inputs

The byte example above is proved by exhaustion. Real cryptography needs
proofs over 2^32-wide words, so the word slice (`ode/word.py`,
`ode/wproducer.py`, `ode/wcheck.py`) replaces exhaustion with symbolic
execution: the checker runs specification and machine over fresh
variables through smart constructors (constant folding, xor cancellation,
canonical add/xor forms, rotr composition and distribution over xor) on a
hash-consed expression DAG, and accepts when both sides reduce to the
same nodes. BLAKE3's `G` and a full 7-round compression are specified in
Ode (`examples/blake3-g.sexp`, `examples/blake3-compress.sexp` -- the
latter generated by `examples/make_compress_spec.py`, the file itself
being the specification of record), compiled to the straight-line W32
machine, emitted to bytes, and proved:

```sh
pypy3 -m ode buildw examples/blake3-g.sexp examples/build-g
pypy3 -m ode checkw examples/build-g          # ACCEPT, symbolic, 33 DAG nodes
pypy3 -m ode buildw examples/blake3-compress.sexp examples/build-compress
pypy3 -m ode checkw examples/build-compress   # ACCEPT, symbolic, 3521 DAG nodes
pypy3 -m unittest discover -s tests           # spec == reference BLAKE3; mutants rejected
```

### Worked example: compute BLAKE3's G on your own inputs

A fresh copy of this repo is all you need. The interface of a word
program is stated in its specification file, so start there:
`examples/blake3-g.sexp` says `(inputs (a b c d x y))` and
`(outputs (a2 b2 c2 d2))` -- G takes four state words and two message
words, in that order, and returns the four updated state words. (The
whole definition is 8 steps; it *is* the interface documentation.)
Then build it, check the proof, and run it:

```sh
pypy3 -m ode buildw examples/blake3-g.sexp /tmp/g   # produce binary + certificate
pypy3 -m ode checkw /tmp/g                          # ACCEPT: the checker re-proves it
pypy3 -m ode runw   /tmp/g 1 2 3 4 5 6               # G(1, 2, 3, 4, msg 5, msg 6)
# 1048782 2275162169 3456900099 3456113664
```

Those four words are the updated `(a b c d)`. Inputs are decimal
(`0x...` works too). The same answer comes from BLAKE3's reference
algorithm, which the test suite cross-checks on 200 random inputs
(`tests/test_blake3_slice.py`); `checkw` is the step that makes the
answer worth trusting for *every* input, not just the one you ran.

Hand-check the run: the specification (`examples/mix.sexp`) is
`mix(x, k) = rotl3((x XOR k) + 60)`, so `mix(60, 165)`: `60 XOR 165 = 153`,
`153 + 60 = 213`, `rotl3(213) = 174`. Then flip any byte of the binary in a
copy of `examples/build/` and run `check` again: it rejects, and the test
suite shows it also rejects a mutant whose hashes were honestly recomputed.
